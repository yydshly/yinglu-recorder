# 映录 · 网页演示录制

面向网页作品演示的 Chrome / Edge Manifest V3 扩展：录制可见网页或固定区域，边操作边用图形、文字、图片讲解，录完本地回看，再自行导出。原生 JavaScript，无运行依赖、账号、后端或水印。

**当前版本：0.6.9。** 本仓库是从原项目目录独立整理的子项目，既有插件加载路径保持不变。

- [项目首页](https://yydshly.github.io/yinglu-recorder/)：能力、效果示意、实现思路与后续计划。
- [工程档案](https://yydshly.github.io/yinglu-recorder/docs/)：架构链路、技术选型、问题修复与源码索引。
- [测试与性能对比手册](https://yydshly.github.io/yinglu-recorder/docs/testing.html)：实机测试步骤、结果模板、历史验证证据。
- [版本记录](CHANGELOG.md) / [详细验证记录](docs/verification.md)。

## 已有能力与边界

| 能力 | 当前行为 |
| --- | --- |
| 网页录制 | 当前视口的完整画面，或鼠标框选的固定视口区域；暂停、继续、停止 |
| 现场标注 | 方框、圆圈、箭头、画笔、多行文字、点击光圈；选择、移动、缩放、撤销、重做 |
| 图片与音乐 | 本地备选图片、参数图与音乐收藏；按需加载，图片可继续加标注 |
| 本地录制库 | 目标约一秒分段写入 IndexedDB；按需回看、下载和直接保存文件 |
| WebM / MP4 | WebM 优先 VP8 / Opus；运行时支持则可录 H.264 / AAC MP4；已有 WebM 可本机重编码为 MP4 |
| 窗口 / 屏幕 | 独立录制页调用系统选择器；基础录制，声音取决于来源和系统 |

「完整网页」指可见视口，不是一次捕获整个长网页。选区固定在视口位置，不跟随 DOM 元素；采集容器像素改变可重新映射，真实 CSS 视口变化或选区越界仍需重新框选。

网页侧栏在标签页采集来源外，标注进入视频；文字编辑框、选中边框与手柄也会进入视频。录整个屏幕可能包含工具窗口，暂不支持桌面级标注。没有时间线剪辑、字幕制作或云同步。

录完隐藏标注，同一网页可点击「显示上次标注」恢复；刷新或关闭网页会清空页内标注。视频不会自动下载。重要录制请手动保存，卸载扩展或清除数据可能丢失本地视频。

## 安装

1. 获取仓库（GitHub「Code → Download ZIP」并解压，或 `git clone https://github.com/yydshly/yinglu-recorder.git`）。已从原目录加载的用户继续使用原目录。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
3. 开启「开发者模式」，点击「加载已解压的扩展程序」，选择**直接包含 `manifest.json` 的目录**。
4. 打开要演示的普通网页，点击映录图标。首次在侧栏点击「开启自动连接网页」，允许普通网站访问；之后切换网页自动识别。来源采集仍受 Chrome 单独授权约束。
5. 点击「开始录制」→ 选择「完整网页」直接开始，或「框选区域」后拖动选区，松开鼠标开始。
6. 点击「操作网页」继续操作作品；按需使用标注。停止后进入录制库回看，自行选择下载原片、直接保存文件或转换 MP4。

无需 `npm install` 或编译。最低 Chrome 116，建议当前稳定版。更新后在扩展管理页点击重新加载，并刷新目标网页。浏览器设置页、扩展商店等受保护页面不能注入标注。

## 性能与数据

- 完整网页满足尺寸 / 帧率条件时优先直录；区域模式多一层视频播放、Canvas 裁切与再捕获，可能增加负载。3D 场景可先试「完整网页 + 流畅 + 30 FPS」，区域卡顿时尝试「一键降低录制负载」。画质与实际收益需要实测。
- 闲置侧栏不启动采集，音乐 / 图片区收起时不打开对应数据库；试听、缩略图、标注历史与恢复图片都有释放或预算控制。预算不等于浏览器进程内存硬上限。
- 超过 32 MiB 的视频按需创建文件预览；OPFS 不可用时不回退大 Blob 预览，可先保存到电脑。文件预览 / 导出需要额外临时磁盘空间。
- WebM 转 MP4 是解码后重新编码，通常接近播放时长，可能改变画质，转换与新采集互斥；不是修改后缀或瞬时无损转封装。
- 数据保存在本机，不上传。无人工录制时长限制，实际受磁盘、浏览器和硬件约束。异常终止只能尝试恢复已落盘片段。

**验证状态：** v0.6.9 已保存 548 项 Node 测试通过记录，以及分版本的浏览器合成媒体、MP4、数据库、标注与文件测试。尚未完成安装扩展后对鹧鸪项目的真实采集与 CPU / GPU / 内存对照，不能宣称实录卡顿或效果丢失已解决。详见 [测试手册](docs/testing.html)；交互预览和历史合成样片不能替代实机验收。

## 本地预览与检查

Node.js 22+，无需额外依赖：

```sh
npm test
npm run check
npm run check:docs
```

Python 3 启动本地静态服务：

```sh
python -m http.server 8765 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8765/> 阅读首页，或 <http://127.0.0.1:8765/demo.html> 体验交互。演示不生成视频，真实扩展录制需要按上文加载插件。浏览器测试入口、证据版本与实机采集方法见 [测试手册](docs/testing.html)。

CI 使用 Node 22 / 24 执行单元测试、语法 / 清单检查和文档内部链接检查；不自动执行 Chrome 扩展实录。

## 实现与目录

```text
index.html / assets/   项目首页（静态、无运行脚本或外部资源）
docs/                 工程档案、性能测试手册、版本化证据
CHANGELOG.md          历史更新记录
manifest.json         Manifest V3 配置
background.js         权限、目标页、会话协调与消息路由
panel.*               侧栏控制台
content.js            Shadow DOM / SVG 标注、文字编辑与框选
offscreen.js          离屏采集承载
lib/recorder.js        MediaRecorder、混音、暂停和分段保存
lib/video.js           来源约束、区域裁切和帧调度
lib/db.js              IndexedDB 分段记录、恢复和列表分页
lib/preview.js         按需文件回看、取消和跨页预览互斥
lib/export.js / mp4.js 导出与本机 MP4 重编码
desktop.*             窗口 / 屏幕录制
library.*             录制库、回看、手动下载与删除
tests/ / scripts/     单元测试、浏览器检查与工程检查
```

网页采集使用 `chrome.tabCapture`，离屏文档通过 `getUserMedia` 消费；桌面采集用 `getDisplayMedia`。编码核心是浏览器 `MediaRecorder`；多路音频才通过 Web Audio 混音，区域视频使用 Canvas 2D / `captureStream`。没有引入 FFmpeg 或 WebCodecs 运行核心。详见 [工程档案的架构](docs/index.html#architecture)和[候选技术路线](docs/index.html#routes)。

## 权限与维护

`activeTab` / `scripting` 用于用户触发后的网页连接和标注；可选普通网站权限支持自动连接。`tabCapture` / `offscreen` / `sidePanel` 支持网页采集和控制。`storage` / `unlimitedStorage` 管理本地设置与录制；`downloads` 仅在用户导出后使用，`alarms` 用于异常任务核对。麦克风、屏幕来源仍需浏览器单独授权。

项目首页通过 GitHub Pages 从 `main` 分支根目录发布，`.nojekyll` 保持静态资源路径。工程档案保留在 `docs/`，原有测试、证据和源码链接持续可用。

公开前请勿加入个人录制、私人素材、诊断中的敏感网址、浏览器配置或凭据。提交时运行上述三项检查；涉及媒体或标注的更改，再执行相应浏览器检查和真实扩展短录。新增性能方案应记录基线、设备、设置、实测结果与适用限制。
