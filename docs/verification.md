## v0.6.7 导出、转换、回看协同与取消保存

完成上一轮列出的前四项高优先级缺口，并加入临时存储空间预检。保持原目录、现有画质 / 帧率选择、分段存储、按需下载；没有新增依赖、扩展权限、数据库迁移或周期轮询。

### 文件生命周期统一

- 新增 `lib/file-resource.js`，由预览、原片暂存、MP4 输出和直接保存共用。目录查询、文件创建、writer、每次写入、提交与 File 读取均使用取消 / 单次等待上限。临时文件创建和原生写入的实际 Promise 单独跟踪，超时后不把迟到资源交给新任务。
- OPFS 资源在创建前持有 Web Lock；取消后立即尝试 abort，界面有界等待清理。只有全部原生变更结束后才删除缓存、释放锁。同页未完成清理会阻止再次叠加同类文件操作。
- `exporter.js` 的后台通知等待有上限，完成下载与取消同时到达时只清理一次。导出页会报告“仍有原生文件清理”；`AutoExporter.finishPage` 收到该状态后保留页面 / 清理占用，不提前关闭、清除保护或启动下一个导出。既有后台清理检查会在结束后再次确认并释放，没有新增轮询周期。
- 用户主动关闭 / 浏览器崩溃仍只能尽力清理，不能物理强杀驱动 I/O。残留由后续所属临时文件回收处理；原始 IDB 录制不作为临时文件删除。

### 内存与存储预算

- `lib/storage-budget.js` 统一内存兼容阈值 32 MiB。大于阈值的原片缺少文件能力时明确失败，保留直接保存入口，不再构造整片 Blob。小片兼容路径保留；磁盘 / 配额错误不能转成内存回退。
- MP4 缺少文件暂存时拒绝已知大源，兼容输出累计超过 32 MiB 时停止；不会只限制等待写入的队列而让已完成 chunks 无限累计。原生编码器内部缓存和单个迟到大块仍由浏览器管理，不能据此承诺进程总 RAM 上限。
- 回看和原片暂存预估对应文件；转换按目标码率、时长估算输出，并在准备来源前估算来源 + 输出所需额外空间。明显不足时在创建 / 复制前提示。
- storage.estimate 只是浏览器对来源配额的估计，不能代表磁盘预留或所有系统空间。缺失 / 拒绝 / 超时的估算不禁用可用功能；写入错误、队列与逐次超时仍负责运行时保护。新增长片没有总时长超时。

### 使用体验与资源协同

- 生产录制库在新录制或转换占用出现时，释放旧播放器来源、URL 和临时缓存；取消尚未完成的预览 / 本地保存准备。结束后只恢复入口，按需载入并恢复播放位置，不自动播放。
- STATE / 桌面消息只唤醒后台核查；仅后台快照决定是否释放，迟到旧会话不会把页面锁住。准备期还没有录制 ID 时也可通过占用状态识别。没有在所有标签之间轮询。
- 多个录制库窗口通过 BroadcastChannel 协同，一个窗口准备 / 播放时释放另一个旧预览；隐藏页暂停播放。原生播放器控件在录制占用时也不能绕过限制。
- 直接保存复用已有取消按钮，标为“取消保存”，信号贯穿选择结果、读取、writer 和提交。文件选择器本身仍等待用户决定；关闭页面会取消后续处理。已提交后收起取消入口，不把已经完成的文件误报为仍可取消。
- 未提交的用户目标 writer 调用 abort，但不删除用户选择的目标文件；原始录制保留。迟到写入未结束前重复保存不会再打开选择器。文件处理完后可重试。后台与侧栏保留清理中的明确提示。

## v0.6.6 取消 / 超时与大图解码峰值

本轮在原目录更新至 0.6.6。保持现有录制、标注、素材和按需下载流程，不增加运行依赖、扩展权限、编辑器或数据库迁移。

### 已修复的等待与迟到资源

- `lib/async.js` 给单次异步操作设置 AbortSignal 与等待上限；资源迟到时调用对应释放，不把旧结果挂到新界面。`lib/db.js` 的读取事务取消时主动 abort；视频导出按片顺序、背压与完整性检查保留。
- `lib/preview.js` 覆盖元数据、目录、游标、文件创建、writer、每次写入、提交和读取 File 的取消 / 超时。读写默认单次 15 秒无进展才超时，没有为大文件设置整个复制过程的总时长上限。小于等于 32 MiB 的 Blob 准备也有等待上限。
- 取消清理最多等待约 1 秒，然后恢复界面。原生创建 / 写入 / 提交尚未结束时，继续保留该缓存的跨页锁；迟到 writer 会 abort，所有底层变更结束后才删缓存并释放锁。原始录制不受缓存清理影响。在同一页面，上次原生文件清理未结束前拒绝叠加另一份预览准备，避免重复点击堆积任务。
- `library.js` 对自身标签信息和后台请求设等待上限；读取占用授权 / 续约超时中断读取，释放最多等待 3 秒，迟到授权再释放。取消不会无限等待释放请求。主动保存文件的 writer 创建 / 提交也有取消与超时；文件选择对话本身仍等待用户决定。
- 超时和取消只让 JS / 界面停止等待，并尽力调用原生 abort；浏览器无法承诺物理强杀磁盘 I/O。底层永久不返回时，保护锁可能保留到页面关闭；异常残留由后续未占用缓存回收处理，不靠周期轮询。读取占用释放失联仍受后台原有过期机制约束。

### 大图导入与峰值

- `lib/image-header.js` 在解码前检查 PNG IHDR、JPEG SOF / EXIF、WebP VP8 / VP8L / VP8X / EXIF。源最多 2000 万像素、单边 10000；损坏 / 无法识别的文件头明确拒绝，压缩文件小不再成为放行巨幅图片的依据。
- 按正确旋转方向计算目标比例，再向 createImageBitmap 请求缩到长边 1600。浏览器没有按目标尺寸返回时拒绝继续，不回退完整尺寸画布。透明 PNG、旋转 JPEG 和普通 WebP 保留正常使用。
- 位图绘制后立即 close；输出和缩略图画布在完成 / 失败时归零。解码、编码分别有 10 秒等待上限，DataURL 读取默认 5 秒。迟到位图关闭，FileReader 取消时 abort；上一原生解码 / 编码未结束前，同页面不并行启动新的导入。
- 侧栏与素材面板关闭会发出取消，移除原先只改变 UI、底层继续处理的 Promise.race。批量处理遇到超时仍停止整批，避免创建一队挂起解码器。
- 2000 万 RGBA 像素理论为约 76.3 MiB，仅是单份源像素量估算；请求缩小后的 bitmap 最多 1600×1600（约 9.77 MiB）。原生解码器可能仍分配源图暂存，浏览器还有编码、GPU、图像缓存；没有测得整个进程内存峰值，也不宣称限制了整个系统资源。

### 区域来源预算

- `lib/video.js` 的普通画质限制整个来源，而非根据选区反向保留高分辨率。高清长边 1920，流畅 / 低负载长边 1280；未知尺寸也请求上限。`offscreen.js` 首次 getUserMedia 即使用相同预算，避免先创建大来源后再降。

### 标注与历史

- 历史使用形状数组的浅快照，未修改的形状和笔迹点数组共享。只有真正编辑时复制被修改的形状；移动 / 缩放从不可变起点生成新点数组，颜色 / 线宽变更直接复用 SVG 路径。文字修改、Undo / Redo、图片几何和资产引用均保持各版本独立。
- 拖动几何变换合并到 RAF，每帧至多一次；pointerup 和工具切换会提交最后待处理坐标。选择本身不复制笔迹，使用缓存边界；仅切工具不重新遍历历史预算。边界计算不再分配两份坐标数组或展开大参数列表。
- 每笔最多保留 4096 点，满时保留首尾并简化旧采样，再继续画；可能减少超长笔迹细节，不会突然停止延伸。当前场景最多 64000 点与 512 图形；当前 / 历史 / 重做合计不同点数组最多 128000 点、快照引用最多 12000、历史最多 50 步。超预算从最旧历史回收。
- 图片按原始 RGBA 像素估算合计 64 MiB，覆盖当前与撤销引用；旧历史回收后释放无用 canvas。预算仍不足则明确提示删除部分图形 / 图片，不影响继续录制。后台只接受目标顶层网页的容量提示，侧栏按当前标签和窗口显示。
- END 保留最后标注以便同页 RESTORE，释放所有 Undo / Redo 历史和未使用图片；恢复后新编辑继续有撤销能力。以上是数据规模预算，不能等同于浏览器全进程 RAM 上限，SVG / GPU / 编码与网页自身仍有开销。

### 大文件回看

- `lib/preview.js`：≤32 MiB 保留轻量 Blob 路径；大于阈值按已有有界 IDB 游标读取，逐片写入独立 OPFS 临时文件，提交后核对大小，再创建 File URL 交给原生 video。没有录制大小的 JS Blob 汇总，也没有新增转码。
- 仍按需点击「载入预览」，支持载入期间取消和载入后的「释放预览」；释放时暂停、移除播放器源、撤销 URL 并删除缓存。video 使用 metadata 预加载，避免主动请求完整预加载。读取锁续约失败或页面关闭时，迟到的资源也会清理；文件缓存独立于原始录制。
- 每个缓存在创建前持有 Web Lock，回收使用 ifAvailable 检查，其他页面仍在用的文件不会删除。打开录制库及准备新预览时清理未持锁残留；无 Web Locks 支持时跳过跨页扫描，仍清理本次自有资源。没有定时清理任务，原有读取续约只在读取期间生效。
- 临时文件或磁盘失败不会静默回退大 Blob；保留重试和直接保存入口。缓存需要与视频近似大小的额外磁盘，首次仍需写完才开播；原生解码 / 缓冲和缺少时长元数据的 WebM 扫描仍有成本，不是零占用、恒定进程内存或分段秒开方案。MP4 转换仍是既有实时重编码，未改造为剪辑流程。

## v0.6.4 性能、暂停与资源释放审查

本轮在原目录更新，没有增加依赖、权限或自动下载。检查范围包括两条视频管线、标注、音频混合、分段写入、预览 / 转换、自动连接及停止清理。

已确认并修复：

1. 区域暂停原先仅跳过绘制，隐藏视频继续播放，原生帧回调及 250ms watchdog 仍递归；没有帧回调的路径还保留 FPS 定时器。现在暂停视频并取消所有裁切调度，继续时按代次恢复一个链，旧回调不能复活。播放恢复失败会停止并保存，而非静默录入旧帧；迟到的旧错误不能影响新一次继续。
2. 原先每次区域绘制调用 `getVideoPlaybackQuality()`；现在原生回调用 `metadata.presentedFrames` 判重，不与不同统计计数混用。诊断快照和没有原生计数的定时兜底仍读取播放统计。新增 `playbackQualityReads` 计数可核验，没有新增采样循环。
3. 裁切输出停止后原先等待 GC 回收画布 backing store；现在停止轨道、暂停并断开视频，归零画布宽高，诊断保持原输出尺寸。
4. 桌面录制页原先无条件每秒更新四次计时。现在只在可见录制中运行一个 1000ms 任务；暂停、保存、完成、隐藏和离页立即取消，状态变化直接更新最终时长。侧栏此前已做同类控制，本轮补齐桌面页。
5. 真实音乐检查复现：试听刚开始就录制，正常停止试听的 play() 拒绝可能显示英文错误。现在按预览来源代次及录制状态过滤过期结果，真正播放错误仍保留。录制音乐也隔离旧播放请求：快速暂停继续不会被旧拒绝改成手动静音，关闭后不发布旧错误。

## v0.6.2 正常切页自动识别与连接恢复

用户要求：刷新仅作兜底，正常切换应自动识别；随后补充界面显示「当前网页待授权」。

排查结论与处理：

- 授权与事件跟随是两条独立条件。当前提示来自 needsActivation，表示尚未获得当前网页的自动连接访问；临时点击扩展图标的 activeTab 权限不会自动延续到其他标签页。现在用突出按钮和直白文字指向「开启自动连接网页」，缺少当前页访问时，即使有旧的自动连接标记也不隐藏入口。不在初始化或切页时自动弹授权框，没有扩充权限。依据：[Chrome Tabs 权限说明](https://developer.chrome.com/docs/extensions/reference/api/tabs#permissions)。
- 旧逻辑只依赖 worker 广播激活消息，且 onUpdated 仅在 complete 后通知侧栏；激活时还没有 URL 就无法判断网站访问。Chrome 明确说明激活事件可能先于 URL 就绪（[官方 onActivated 说明](https://developer.chrome.com/docs/extensions/reference/api/tabs#event-onActivated)）。新侧栏直接订阅 onActivated / onUpdated，地址就绪立即查询当前窗口并连接；缺地址的加载期显示等待加载，不误报待授权。后台给兼容路径发送同类事件，侧栏能直接订阅时忽略重复转发。
- 旧自动失败缓存只在导航、权限变化或手动重连时释放，同 URL 的加载完成、切走再切回仍沿用旧失败。新激活与 complete 使该页旧缓存及待处理 attach 失效，迟到的旧文档结果不能污染新连接；同一次失败后的普通查询仍不无限重试。
- 窗口焦点恢复时补查可能遗漏的事件；多个同步事件合并到一个微任务。忽略其他窗口、后台标签及声音等无关变化；已连接页标题变化直接更新标题，不重新握手。隐藏不发查询，关闭移除 Tabs 订阅并作废在途结果；录制期间继续锁定原来源。没有新建录制器、持续定时器或轮询。

## v0.4.9 自动连接与空闲资源管理

用户反馈侧栏长期显示连接中，要求切换网页自动识别，并降低对操作系统的影响。

代码分析发现普通连接的网页读取、PING、注入与二次握手没有等待上限；连接中状态跨 worker 重启保留，但缺少有效期和活跃请求身份。旧方案只有 activeTab，未授权的新页只能提示再次点击图标。这些是确认的实现缺口，未取得用户当时卡住的运行日志，不能认定某一个就是现场唯一根因。

本轮修改：

- 新增可选 HTTP / HTTPS 网站访问授权，仅在用户点击侧栏按钮时申请；授权后侧栏 GET_STATE 按所属窗口连接当前页。标签切换、加载完成、重新可见触发查询，关闭或隐藏侧栏不自动注入全浏览器。连接失败缓存最多 32 项，刷新页面、手动重试或权限变化可重试，无持续后台重试。
- 单个连接阶段有界；同页并发注入合并，连接请求带身份，超时失败和 worker 重启不永久保留连接中；迟到连接结果不覆盖新目标。面板状态查询和重连等待也有兜底，超时后退出识别中提示。
- 计时器仅在录制中且侧栏可见时每秒更新；空闲、暂停、隐藏及 pagehide 清除，文字相同不重写。默认不开启 RAF / 长任务诊断，继续尊重明确保存的用户设置。无相关读取占用的普通网页导航不再空写 session storage。
- 保留录制来源锁定、停止释放采集以及手动回看与下载规则。本轮不改变媒体裁切和编码路径，不安装 OS 服务或修改 OS 设置。

## v0.4.5 Chrome 固定采集帧与区域映射

日期：2026-10-19。用户确认使用 0.4.4，区域录制一直提示“采集画面尺寸尚未稳定”。截图显示网页已连接、计时为零；截图中的 1395 × 896 是框选尺寸，不等于已取得真实采集流尺寸。

- 只有 offscreen 中明确来自 Chrome 标签页的流标记 `captureLayout:'chrome-tab'`。按已确认的 CSS 视口和实际采集帧计算居中内容矩形，再将选区映射到内容矩形，包含补边偏移；I420/NV12 常见偶数帧按色度采样边界对齐。

- 未将该布局假设套给桌面、窗口或未知来源，其原有比例检查保留。没有删除选区越界、取消、会话与 CSS 视口保护，也没有靠延长超时绕过错误。
- 诊断增加 `captureLayout`、`contentRect`、`cropRect`。通用来源的尺寸不匹配错误改为明确的“不匹配”，附视口与帧尺寸；detail 经 Recorder 状态、offscreen、background 返回侧栏，避免只剩笼统提示。

1. 已查看鹧鸪页面及公开项目源码。入口通过 iframe 按需运行单个作品；顶层 RAF 调度并不等同于 iframe 内 WebGL 帧率，跨 iframe 的上下文丢失也不在顶层采样范围。需要测量作品本身时，应使用页面的「独立打开」。
2. 源码中有 DPR 上限 1.8/2、抗锯齿、2048 阴影等渲染设置，部分实现开启 preserveDrawingBuffer。这些是 GPU 负载的候选因素，不能仅凭静态代码确定本次崩溃原因；没有改鹧鸪项目源码，也没有强制降低网页效果。
3. 轨道 frameRateSetting 是设置值；页面 RAF 是调度节拍；Canvas 提交耗时不含完整 GPU/编码耗时。都不是成片实际 FPS。短基线/隐藏页面明确标为不足或未采集，长录制保留最近 60 个录制中样本。

## v0.2.2 多标签页与多窗口侧栏

权限不变：首次在新标签页使用仍需用户点击扩展图标取得 activeTab 授权，没有添加全站访问权限。依据 Chrome 官方 [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) 和 [当前窗口](https://developer.chrome.com/docs/extensions/reference/api/windows#the-current-window) 文档。
