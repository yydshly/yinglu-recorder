起点

让网页演示自然发生

项目来自录制鹧鸪网页作品 ↗的需求：既要展示动画和交互，也要通过点击、框线、箭头和文字表达讲解。即使不标注，它也应当是完整可用的录制工具。

当前定位是网页演示优先，同时提供窗口 / 屏幕基础录制。没有账号、服务端和水印，不设置人为录制时长限制；实际能力仍受浏览器、设备与磁盘约束。

已确认的体验约定

  • 鼠标可操作工具，网页模式侧栏在采集范围外。
  • 先点开始，再选完整网页或拖动框选。
  • 标注随操作进入视频，结束后收起。
  • 录完先存库回看，用户自己选择是否下载。

展开容量预算和保护阈值
  • 来源：高清长边预算 1920，流畅 / 低负载 1280；原始尺寸保留细节优先。低负载 20 FPS，设置值不是成片实测帧率。
  • 视频：目标约一秒分段，待写入超过 64 MiB 触发停止；32 MiB 内允许 Blob 兼容路径，超过后依赖文件路径，暂存额外占磁盘。
  • 标注：512 个图形、单笔 4096 点、场景 64000 点；当前与历史共保留 128000 点，撤销最多 50 步并受引用预算约束。
  • 图片：输入先预检，输出长边最多 1600；素材库 12 张 / 16 MiB，页内像素预算 64 MiB、压缩恢复 16 MiB。
  • 音乐：12 首，单首最多 32 MiB / 60 分钟，合计 128 MiB；实际解码由浏览器管理。
  • 列表：录制库每次 20 条，侧栏最近 3 条，更多内容按需载入。

实现依据：标注预算、文件预算、图片素材、音乐库。不同层的保护预算不能相加视为真实 RAM，更不代表 Chrome 进程硬上限。

03 / ARCHITECTURE

画面如何变成视频

捕获、处理、编码、保存是四件事。产品界面与录制底层分别承担职责。

控制面操作与协调

Side Panel

panel.*

范围、工具、音频、素材、状态；发送控制消息，不持续编码视频。

Service Worker

background.js

权限、目标页、会话身份、采集 / 转换互斥与恢复。会休眠，媒体不依赖它常驻运行。

Content Script

content.js / Shadow DOM + SVG

在目标网页绘制文字、图形和图片；进入网页像素，也会增加网页的主线程 / 合成工作。

控制消息：侧栏 → 后台核对来源与会话 → 网页标注层 / 媒体承载页；承载页回报状态。录制开始后不随空闲连接逻辑切换来源。

媒体承载运行位置

网页离屏文档

offscreen.js

消费后台 tabCapture 流 ID，以 getUserMedia 取得来源。关闭侧栏仍可录制，结束后清理离屏资源。

独立桌面录制页

desktop.js

执行 getDisplayMedia、来源预览 / 框选，调用共享 Recorder；关闭录制页会中断。

独立导出任务页

exporter.js / lib/mp4.js

准备下载文件、解码重编码、进度与取消。与采集协调占用，保护尚未结束的原生操作。

共享核心处理与编码

视频输出

lib/video.js

整幅来源满足条件则直用；裁切 / 缩放使用视频 → Canvas 2D → captureStream，随新帧调度。

音频与录制

lib/recorder.js / music-player.js

单音轨直接使用，多路 Web Audio 混音；MediaRecorder 编码、暂停、分段背压和终结。

文件生命周期

lib/file-resource.js / preview.js

创建、逐段写入、提交、取消与迟到清理；锁保护活跃文件，播放器与 URL 按需释放。

媒体数据：目标来源（含网页标注）→ 直录或裁切 + 按需混音 → MediaRecorder → IndexedDB 片段 → 回看 / 手动导出。视频字节不会逐帧通过侧栏或后台消息。

数据面保存与释放

持久本地数据

IndexedDB / storage.local

视频元数据与片段、图片 / 音乐分库；偏好与必要任务摘要另存。卸载或清数据可能丢失。

会话与页内数据

storage.session / 页面内存

协调状态、来源和占用；最终标注保留在网页，隐藏后图片留压缩恢复数据，不跨刷新。

临时与用户文件

OPFS / 文件选择器 / downloads

OPFS 用于回看和暂存，不是备份；用户主动保存到电脑的文件独立保留。

离屏运行分离了控制界面与媒体生命周期，但仍共享设备的 CPU / GPU / 内存，不自动消除采集、合成和编码成本。接口配合参照 Chrome 官方采集说明；下方四条链路对应当前实现。

优先直接编码标注已包含在网页像素中
  1. 01 · 捕获Chrome 标签页chrome.tabCapture

    取得目标页画面与声音的流标识。

  2. 02 · 接收离屏媒体流getUserMedia

    离屏文档消费来源，尝试约束尺寸与帧率。

  3. 03 · 编码原生录制器MediaRecorder

    满足条件时直接编码来源轨道。

  4. 04 · 保存本地片段IndexedDB

    约一秒目标分段，结束后在库中回看。

为什么优先这条路径

减少额外的视频播放、Canvas 重绘与再次捕获。来源不满足约束时仍可能回退到 Canvas，不能把“完整网页”一概当成直录。

增加逐帧处理CSS 选区 → 实际采集像素
  1. 01 · 确认稳定网页视口tabCapture + 握手

    采集就绪后确认选区、CSS 尺寸与可用采集画面。

  2. 02 · 裁切视频 → CanvasdrawImage

    先计算网页内容矩形、剔除采集补边，再映射选区；优先跟随新视频帧。

  3. 03 · 输出画布媒体流canvas.captureStream

    将裁切画面交给 MediaRecorder 编码。

  4. 04 · 保存本地片段IndexedDB

    保持输出尺寸，保存已有片段并提供预览。

尺寸保护与开销

Chrome 标签页固定帧的上下 / 左右补边会纳入坐标换算；容器尺寸改变可重新映射。真实 CSS 视口变化或选区越界仍会要求重选。Canvas 路径增加处理成本，实际影响尚需鹧鸪实机对照。

基础通用录制独立录制页承载，声音取决于来源
  1. 01 · 来源系统选择器getDisplayMedia

    用户选择窗口或屏幕，并按需共享声音。

  2. 02 · 处理直接 / 区域输出createVideoOutput

    整幅画面优先直接使用，框选时裁切。

  3. 03 · 编码共享录制核心MediaRecorder

    复用暂停、停止、音频与异常处理。

  4. 04 · 保存录制库IndexedDB

    完成后自行回看、下载或转换。

与网页模式不同

当前没有桌面级标注。录整个屏幕可能包含可见控制窗口，不承诺工具条隐身；关闭独立录制页会中断录制。

本机重新编码转换期间与新采集互斥
  1. 01 · 读取已保存的 WebMIndexedDB → OPFS / Blob

    取得读取占用，检查片段顺序与总字节数。

  2. 02 · 解码视频播放流HTMLVideoElement

    解码原视频并提供进度、取消能力。

  3. 03 · 编码H.264 + AACMediaRecorder

    运行时检测真实 MP4 能力，保留原件。

  4. 04 · 导出用户选择下载chrome.downloads

    核对实际下载状态，清理临时文件。

不等于更改文件后缀

这条路径通常接近播放时长，并可能改变画质、大小；不是瞬时无损转封装。直接选择 MP4 录制可省去这次转换，前提是运行环境支持。

⌘

控制与标注，分开安放

Side Panel 承载鼠标操作的工具；Content Script 用 Shadow DOM / SVG 绘制图形、文字和点击光圈。后者成为网页像素进入视频，侧栏不属于标签页来源。工具排除尚待鹧鸪成片实测确认。

LIFECYCLE

启动、停止与恢复各自负责什么

连接网页→选择范围→准备来源→录制 ↔ 暂停→释放采集→保存终结→按需回看 / 导出

空闲与暂停

仅打开侧栏不启动采集；收起的素材区不打开对应数据库。暂停取消裁切调度并暂停隐藏视频，但保留来源以继续录制。数据库复用连接不等于素材常驻解码。

正常停止

停止编码与采集，断开媒体 / 音频和画布；标注隐藏、释放历史，保留恢复所需数据。随后等待分段写入与终态保存，界面区分保存中、完整和部分保存。

取消、超时与迟到操作

停止继续发起后续工作，隔离过期结果。原生 I/O / 解码不能保证立即强杀；对应操作结束后才删文件、释放锁，避免误清理新会话或并行堆积。

失联、重启与回看

后台核对实际媒体承载页和任务，尝试终结已落盘记录；不保证崩溃末段完整。回看 / 导出按需创建临时文件，使用结束清理所属资源，异常残留按占用保护回收。

04 / DECISIONS

为什么这样实现

保留选择背后的原因，也记录它带来的代价。

D01

先做浏览器扩展 当前采用

网页作品是主要来源，扩展容易注入标注、连接目标标签页，并把控制区放在侧栏。原生 JavaScript、无需运行依赖或后端。

代价：来源权限、service worker 休眠、浏览器版本和媒体能力都需要处理。

D02

标注直接进入网页画面 当前采用

用户希望保留现场操作的自然感。用 SVG 图形和可编辑文字完成实时标注，鼠标可切换操作网页、绘图与选择。

代价：标注已经烘焙进视频，不能在成片中独立编辑；编辑框、选中边界和手柄也可能录入。结束后隐藏，同页可恢复，刷新会清空。

D03

整页优先直录，区域才裁切 当前采用

整页满足尺寸与帧率条件时直接编码；裁切优先跟随视频帧，跳过重复帧，暂停时停止重绘。单音轨直接使用，多路时才混音。

代价：区域多一道 Canvas 处理；尺寸要在 CSS 像素与采集像素间一致换算。30 / 60 FPS 是目标，不代表实测成片帧率。

D04

分段落盘，保存与采集分别收尾 当前采用

约一秒目标的片段写入 IndexedDB，减少仅在内存积累整片的风险。停止先释放来源，再等待保存；启动、写入、停止和清理均有异常兜底。

代价：浏览器调度不能保证每段刚好一秒；崩溃仅能恢复已落盘片段。完整预览与 Blob 兼容路径仍可能消耗较多内存。

D05

录完回看，由用户选择下载 0.4.3 调整

保留分段存库，取消录完自动下载。用户主动预览、保存原片、分段写文件，或转换 MP4；旧版未真正下载的自动任务也暂停。

代价：本地库不等于外部备份。卸载或清除扩展数据可能丢失录制，需要用户主动保存重要视频。

D06

真实编码 MP4，保留原始视频 当前采用

WebM 优先 VP8 / Opus；MP4 检测 H.264 / AAC 支持。已有视频转换使用本机解码和重新编码，不上传；转换期间与采集互斥，避免同时争用编码资源。

代价：转换通常接近实时、可能改变画质。当前未使用 FFmpeg 或 WebCodecs 作为运行核心，也没有通用无损转封装。

路线的差别，在处理链路

换产品外壳不等于换采集与编码核心。以下是现状与候选方向，不是已经承诺的升级。

录制技术路线比较
路线 / 状态能带来的价值限制与成本对映录的判断
浏览器 + MediaRecorder当前实现网页集成直接；扩展较轻；标注和侧栏协同方便。编码控制较少，区域处理增加开销，生命周期与存储需兜底。继续作为网页演示主线，先建立实机基线。
浏览器 + WebCodecs候选 · 未实现更细控制帧、时间戳与编码队列；可把部分处理放到 Worker。自行负责音画同步、文件封装、背压与内存；仍使用浏览器来源，不保证更快。实测确认帧处理或编码控制是瓶颈后再做原型。
Region / Element Capture候选 · 未验证由浏览器裁切区域或限制元素，可能减少手动逐帧处理。存在 self-capture 和目标元素条件；元素捕获可能排除独立标注层，不能直接替换离屏任意页采集。先验证可用上下文、标注保留及尺寸行为。
系统采集 + 原生编码候选 · 未实现更灵活的窗口 / 屏幕来源、GPU 处理、编码控制和大文件管理。需要安装程序及各系统适配；权限、音频、显卡和崩溃恢复成本更高，仍会争用资源。通用录屏、高负载和长时间录制的长期候选。
Electron / Tauri 外壳形态选择 · 未实现便于桌面界面、文件管理和原生模块集成。仅套壳仍可能沿用浏览器媒体链路，不自动提升性能。只有接入不同的录制核心，才构成底层切换。
插件 + 本机原生进程长期构想插件负责网页操作与标注，本机进程负责采集、编码和文件。增加安装、通信、坐标同步与两端版本管理；控制区排除和标注合成需重新设计。保留现有交互成果的演进方式，暂不进入重写。
两个判断边界

MediaRecorder 也可能使用硬件编码，具体取决于设备、格式和浏览器。原生采集有优化空间，但无法补回网页自身未渲染的帧或已经丢失的效果；更换路线前必须做相同条件的对照。

10 / NEXT STEPS

下一步，先测清楚再换路线

下面按依赖与优先级排列，没有承诺发布日期，也没有把候选方案记为已实现功能。

  1. A · 真实录制验收 下一步 / P0

    交付：鹧鸪固定场景下「仅开侧栏 / 整页 / 区域」对照、原片与 MP4、标注操作、停止后恢复记录。

    进入下一阶段的条件：能区分页面渲染、逐帧裁切、编码、保存与回放的影响；成片效果、工具排除、音画和资源回落有可复核证据。方法见测试手册。

  2. B · 性能与可靠性收敛 依赖 A / P1

    交付：只针对实测瓶颈的小改动；真实长录制、多窗口、权限拒绝、空间不足、浏览器重启、取消与清理矩阵。

    退出条件：同条件复测有收益且不损失文字 / 图片 / 音轨；未发生错会话写入和重复任务，失败保留原件、状态可理解。用相同设备与设置比较，不用合成次数代替系统占用。

  3. C · 轻量使用性完善 稳定性优先 / P2

    交付：从高频反馈中选择少量入口改善，例如更清楚的来源检查、素材命名 / 排序、可选标注草稿；复用现有偏好记忆，保持默认流程和权限简单。

    退出条件：准备演示所需操作减少，闲置开销无明显回退；不新增默认常驻解码、轮询、上传或复杂编辑流程。

  4. D · 处理路径试验 瓶颈证据触发 / 候选

    交付：浏览器原生裁切、Worker / WebCodecs 或原生采集中的一个最小原型，与现有路径做同条件对照。

    进入主线的条件：确认来源授权、任意网页适用性、固定选区与标注保留，收益足以覆盖同步、封装、兼容和维护成本。原型不通过则保留当前主线。
